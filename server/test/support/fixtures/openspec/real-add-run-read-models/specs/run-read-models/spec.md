## ADDED Requirements

### Requirement: Agent 的可派发性

系统 MUST 提供只读函数，对当前工作区每个托管、未归档的 Agent，以当前用户作为授权来源给出能否派发：可以，或跳过及原因（Agent 已停用、无权触发、未绑定运行时、运行时已禁用，按此顺序判定），并附它绑定的运行时（所在机器名、CLI、在线状态、是否禁用）。运行时离线 MUST 视为可以派发。需要读取任务的权限。查询次数 MUST 与 Agent 数量无关。

#### Scenario: 无权触发
- **WHEN** member bob 查询，`keel/dev` 的访问范围是「仅所属用户」且所属用户是 alice
- **THEN** `keel/dev` 的结果为跳过、原因 `unauthorized`

#### Scenario: 运行时离线
- **WHEN** alice 查询，`keel/dev` 绑定的运行时离线
- **THEN** `keel/dev` 的结果为可以，运行时状态为 `offline`

### Requirement: 任务的运行中 Agent

系统 MUST 提供只读函数，对一批任务 ID（最多 200 个）返回每个有已领取、运行中或停止中运行的任务上，这些运行的 Agent 名（按领取先后、去重）；没有这类运行的任务不出现。需要查看运行的权限。MUST 只用一条查询。

#### Scenario: 列表标记
- **WHEN** `BOS-1` 有一条运行中的 `keel/dev` 运行，`BOS-2` 只有已结束的运行
- **THEN** 结果只有 `BOS-1 => ["keel/dev"]`

### Requirement: Agent 用量

系统 MUST 提供只读函数，返回某个托管 Agent 最近 N 天（1–90，含今天，UTC）每天结束的运行按结果的计数、输入与输出令牌数和费用，以及区间合计；缺的天补 0；未报告的令牌数按 0 计，某天全部运行都没有费用时该天费用为空。外接 Agent 或不存在的名字 MUST 返回不存在；存在但区间内没有运行的 Agent MUST 返回全 0 的结果，而不是不存在。需要查看运行的权限。

#### Scenario: 按天分桶
- **WHEN** `keel/dev` 今天成功 2 次（输入令牌 100、50）、失败 1 次（未报告用量），查询最近 7 天
- **THEN** 返回 7 天，最后一天 `succeeded` 为 2、`failed` 为 1、`input_tokens` 为 150；其余 6 天全为 0；合计运行数为 3

### Requirement: Agent 视图与权限

Agent 的列表与详情视图 MUST 带最近一次运行的创建时间（没有为空）以及它所在的工作区与 actor 标识，且不因此对每个 Agent 单独查询。系统 MUST 提供纯函数，按与授权检查相同的规则（含资源必须属于当前工作区）给出当前用户能否配置、能否管理某个 Agent；视图不属于当前工作区时 MUST 都为否。

#### Scenario: 权限与授权检查一致
- **WHEN** 对每种角色（owner、admin、member 本人、member 非本人、viewer）与运行 scope 计算 `alice` 的 Agent 的权限
- **THEN** 结果与对同一操作调用授权检查的结果完全相同

#### Scenario: 跨工作区的视图
- **WHEN** alice 在工作区 A 是 viewer、在工作区 B 是 admin，两边各有同名 Agent `keel/dev`；以 A 的 scope 计算 B 的 `keel/dev` 视图的权限，以及以 B 的 scope 计算 A 的视图
- **THEN** 两种组合的配置与管理都为否，与对相应 actor 调用授权检查的结果相同

### Requirement: 未结束的运行

系统 MUST 提供只读函数，对一个任务或一个托管 Agent 返回：全部已领取、运行中、停止中的运行（按领取先后，不分页）；排队与延后的运行（按领取顺序：优先级高的在前，同优先级先入队的在前）——对任务 MUST 完整返回，对 Agent 返回一页，可用游标翻页、每页最多 200 条；以及排队与延后的总数。结果 MUST 与已结束运行的数量无关。每次调用 MUST 按调用时的状态给出正确的一页与精确的总数；两次调用之间运行发生变化时不保证沿用旧游标不重复不遗漏，调用方应从第一页重读。需要查看运行的权限；任务或 Agent 不存在 MUST 返回不存在。

#### Scenario: 任务的排队完整返回
- **WHEN** 任务 `BOS-1` 有 51 条排队或延后的运行（不同 Agent）
- **THEN** 一次调用返回全部 51 条，总数为 51

#### Scenario: 优先级升高后重读
- **WHEN** 以每页 2 条读取 `keel/dev` 的排队运行第一页之后，一条原本排在第二页的运行因合并触发升为更高优先级
- **THEN** 从第一页重读时它出现在正确的位置，且整个重读结果中每条运行只出现一次

#### Scenario: 活跃与排队分开
- **WHEN** `keel/dev` 有 2 条运行中、3 条排队（优先级 3、2、2）、100 条已结束的运行，以每页 2 条查询
- **THEN** 活跃为那 2 条；排队一页为优先级 3 与先入队的那条优先级 2；排队总数为 3；用最后一条作游标取下一页得到剩下的 1 条

### Requirement: 已结束的运行

系统 MUST 提供只读函数，对一个任务或一个托管 Agent 按创建时间新到旧分页返回已结束（成功、失败、已取消）的运行，每页最多 100 条，用游标翻页，并给出调用时已结束运行的总数。已结束的运行在这个顺序中的位置 MUST 不再改变；新结束的运行可能出现在任何位置，调用方应在运行变化后从第一页重读。需要查看运行的权限；任务或 Agent 不存在 MUST 返回不存在。

#### Scenario: 翻页不重复不遗漏
- **WHEN** 任务有 120 条已结束运行，以每页 50 条连续翻页，第二页之前一条早先创建的运行结束了
- **THEN** 原有的 120 条在三次调用的结果中各出现恰好一次；新结束的那条可能出现在后面的页里，也可能不出现（它排在已读过的位置）；之后从第一页重读到 121 条时它出现在按创建时间应在的位置，没有重复；每次调用给出的总数都是当时的精确值

### Requirement: 守护进程在线

本人的守护进程列表 MUST 给出每台是否在线：未吊销且最近一次上报在在线阈值之内；该阈值 MUST 与把运行时标为离线的判定使用同一处定义。

#### Scenario: 刚超过阈值
- **WHEN** 守护进程最近一次上报在 121 秒前（阈值 120 秒）
- **THEN** 列表中该守护进程不在线
